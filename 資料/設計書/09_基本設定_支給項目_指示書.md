## 1. 画面概要

| 項目 | 内容 |
|---|---|
| 画面名 | 基本設定／支給項目（支給項目設定） |
| 目的 | 給与計算で使用する「支給項目」のマスタを、給与区分（月給／時給／日給／賞与）ごとに定義する。項目の有効／無効、計算方法（数式・従業員情報参照・手入力等）、税・保険計算への算入可否などを設定する |
| 主要ユーザー | 給与担当者（管理者権限） |
| 表示トリガー | サイドナビ「基本設定」→タブ「支給項目」 |

## 3. コンポーネント仕様

### 3-1. 基本設定タブ共通ナビゲーション

| 要素 | 内容 |
|---|---|
| タブ項目 | 全般／住民税／事業所／支給項目／控除項目／勤怠項目／社会保険／労働保険／年度／明細／システム |
| 選択状態 | 選択中タブは下線＋青字（[[04_給与計算_設計書]]・[[05_従業員情報_指示書]]のタブ意匠と同系統） |

→ [[10_基本設定_控除項目_指示書]]・[[11_基本設定_勤怠項目_指示書]]も同じ共通ナビゲーションを共有する兄弟画面。

### 3-2. 給与区分サブタブ

| 要素 | 内容 |
|---|---|
| タブ項目 | 月給／時給／日給／賞与 |
| 選択状態 | 選択中はピル型ボタンで紺背景＋白文字。未選択はグレー文字 |
| 挙動 | タブ切替でテーブルの行構成・項目内容が別マスタに切り替わると推測（本キャプチャは「月給」タブのみ取得、他タブは8章参照） |

### 3-3. 支給項目テーブル（列構成）

| 列 | 内容 |
|---|---|
| 支給項目 | チェックボックス（有効／無効）＋項目名。一部項目名の右に「?」ヘルプアイコン、または項目名自体がテキスト入力欄（カスタム項目は編集可能） |
| 計算方法 | ドロップダウン（下記3-4参照）。項目により「÷[数値]×[倍率]×[時間数/日数ドロップダウン]」の数式ビルダー形式、または「従業員情報で設定」の固定文言表示（数式欄なし） |
| 時間数/日数 | 割増賃金系の項目のみ、単位ドロップダウン（例：所定外時間（平日）、法定外時間（平日）等）を表示 |
| 詳細設定 | ボタン。クリックでポップオーバー形式の詳細設定モーダルを開く（無効項目はボタンもグレーアウトで押下不可） |
| 削除アイコン | 🗑（赤）。カスタムで追加した行にのみ表示。システム標準項目には表示されない＝標準項目は削除不可、カスタム項目のみ削除可能という制約 |

### 3-4. 「計算方法」ドロップダウンの選択肢

| 選択肢 | 意味（推測含む） |
|---|---|
| 毎月手入力 | 給与計算時に金額を都度手入力する項目（例：遡及支払額、立替経費） |
| 従業員情報で設定 | 従業員マスタ（[[05_従業員情報_指示書]]の業務情報カード等）に登録された固定額・条件を参照 |
| 割増基礎 | 残業・休日・深夜等の割増賃金の計算基礎額を参照する数式 |
| 前月の割増基礎 | 割増基礎の前月分を参照（賞与計算等での利用と推測） |
| 控除基礎 | 欠勤控除・遅刻早退控除等の計算基礎額を参照する数式 |
| 前月の控除基礎 | 控除基礎の前月分を参照 |
| カスタム計算式 | 選択後「保存する」を押すと、任意の計算式を設定できる（詳細UIは未取得） |

- 数式ビルダーは「[計算方法] ÷ [数値] × [倍率(例:1.0/1.25/1.35)] × [時間数/日数ドロップダウン]」の固定フォーマット。割増率（残業1.25、深夜0.25、法定休日1.35等）はこの倍率欄に初期値としてプリセットされている

> 📌 **公式サポートサイトでの補足確認**（[「支給項目」の設定方法](https://biz.moneyforward.com/support/payroll/guide/setting/se11.html)より）：計算基礎（割増基礎／控除基礎等）を除算する項目では、「所定労働時間（日単位・月単位・月平均）」または「所定労働日数」で除算できる旨が明記されている。また「前月の割増基礎」「前月の控除基礎」のような前月実績を参照するオプションは、各計算基礎の項目ごとに用意されている構造であることが確認できた。

### 3-5. 詳細設定モーダル

| 要素 | 内容 |
|---|---|
| チェック項目群 | 所得税の計算対象／労働保険の計算対象／社会保険の計算対象／固定的賃金(月額変更用)／現物／割増基礎／控除基礎／休職・休業の計算対象／0円でも表示／日割り計算基礎 |
| 計算符号 | ラジオボタン「プラス計算」／「マイナス計算」（欠勤控除等マイナス項目用と推測） |
| 端数処理 | ドロップダウン：切り上げ／四捨五入／切り捨て |
| 操作 | 「閉じる」ボタンのみ（モーダル内に個別の保存ボタンはなく、画面下部の「保存する」で一括保存する設計と推測） |

→ このモーダルのチェック項目が、[[04_給与計算_設計書]]で確認した「従業員の契約条件によって支給・控除項目の行数が変動する」動的テーブルの制御ロジックの正体。「社会保険の計算対象」「所得税の計算対象」等のフラグが、他画面（社会保険設定・住民税設定等）の計算式にどの支給項目を合算するかを決めている構造と推測される。

> 📌 **公式サポートサイトでの補足確認**（[「支給項目」の設定方法](https://biz.moneyforward.com/support/payroll/guide/setting/se11.html)より）：詳細設定の各チェック項目の意味について、「固定的賃金(月額変更用)」は社会保険の月額変更手続き（随時改定）用に対象支給項目を指定するものであり、「現物」は現金支給から除外した上で標準報酬月額の算定に使用する項目を指定するものである旨が明記されている。「端数処理」の具体的な仕様（切り上げ／四捨五入／切り捨ての適用単位等）については、記事内でも別ページへのリンク参照のみで詳細説明はなく、依然未確認。

### 3-6. 行の追加・削除

| 要素 | 内容 |
|---|---|
| ＋追加ボタン | クリックでテーブル最下部に新規カスタム行を追加（項目名は自由入力） |
| 削除アイコン | カスタム行のみ🗑で削除可能 |
| 保存する | 画面下部固定の金色ボタン。全行の設定をまとめて保存 |

> 📌 **公式サポートサイトでの補足確認**（[「支給項目」の設定方法](https://biz.moneyforward.com/support/payroll/guide/setting/se11.html)より）：支給項目は給与区分（月給／時給／日給／賞与）ごとに完全に独立したマスタであり、**複数の給与区分で同じ項目を使いたい場合でも、区分ごとに個別に「＋追加」で項目を作成する必要がある**（項目定義そのものは区分間で共有されない）旨が明記されている。

### 3-7. カスタム計算式（「計算方法」で「カスタム計算式」を選択した場合）

> 📌 **公式サポートサイトでの補足確認**（[カスタム計算式の設定方法](https://biz.moneyforward.com/support/payroll/guide/setting/se13.html)より）：計算方法で「カスタム計算式」を選択後、「計算式を設定」から専用の入力フォームが開き、以下の要素を組み合わせて数式を構築できる。
> - **計算の基礎**：従業員情報で設定した値／割増基礎／前月の割増基礎／控除基礎／前月の控除基礎／時給／日給
> - **支給項目・勤怠項目**：設定済みの他の支給項目・勤怠項目を参照可能
> - **数値**：小数を含む自由入力
> - **四則演算**：＋／－／÷／×
> - **関数**：ROUND（四捨五入）／ROUNDUP（切り上げ）／ROUNDDOWN（切り捨て）／IF（条件分岐）
>
> また、文章から計算式案を自動生成するAI提案機能（ChatGPT API利用）も用意されている旨が確認できた。なお同記事は月給制の支給項目設定画面を前提に説明しており、他の給与区分（時給／日給／賞与）や控除項目でも同様に使えるかは記事からは明言されていない。

## 4. データ構造（項目定義）

### 支給項目マスタ（月給タブで確認できた項目・区分別）

| 区分 | 項目名例 | 備考 |
|---|---|---|
| 基本給系 | 役員報酬、基本給、役職手当、家族手当、住宅手当、営業手当 | いずれも「従業員情報で設定」型（従業員ごとの固定額を参照） |
| 割増賃金系 | 残業手当、法定内残業手当、深夜残業手当、法定休日手当、所定休日手当 | 「割増基礎 ÷ 所定労働時間(月平均) × 倍率 × 時間数/日数」の数式型。倍率は残業1.25、深夜残業0.25、法定休日1.35、所定休日1.25等がプリセット |
| 控除系（支給項目タブ内） | 欠勤控除、遅刻早退控除 | 「控除基礎 ÷ 所定労働時間/日数(月平均) × 1.0 × 欠勤日数・遅刻早退時間」の数式型。マイナス計算として扱われると推測 |
| 通勤手当系 | 通勤手当/課税、通勤手当/非課、現物通勤手当/課税、現物通勤手当/非課 | 「従業員情報で設定」型。課税・非課税で別項目として分離管理 |
| 手入力系 | 遡及支払額、立替経費 | 「毎月手入力」型 |
| 固定残業手当系 | 固定残業手当（みなし）、固定残業超過分手当、固定深夜残業手当（みなし）、固定深夜残業超過分手当、固定休日労働手当（みなし）、固定休日労働超過分手当 | みなし残業代制度に対応する項目群。超過分は「固定残業時間（みなし）」を差し引く数式（例：法定外時間(平日) − 固定残業時間（みなし）） |
| その他標準項目 | 日割り計算控除 | 「日割り計算を設定」の専用UIへのリンクと推測（詳細未取得） |
| カスタム項目例 | 時給1、紹介料 | 項目名を自由入力できる追加行。削除アイコン付き |

→ この一覧が[[04_給与計算_設計書]]の給与内訳テーブル「支給」カラムの元データ（マスタ）である。給与計算画面では、ここで有効化（チェックON）した項目のみが従業員ごとの明細に表示される関係。

> 📌 **公式サポートサイトでの補足確認**（[「日割り計算控除」の設定方法](https://biz.moneyforward.com/support/payroll/guide/setting/se16.html)より）：「日割り計算控除」にチェックを入れ「日割り計算を設定」ボタンから開く詳細設定では、支給対象期間の途中で入退社・休職・復職した従業員について自動で日割り控除額を計算する条件を設定する。設定可能な要素は以下の通り。
> - **対象者の条件**：当月の入社者／退職者、当月の休職者／復職者、任意の詳細条件
> - **控除額計算式**：出勤日数計算方式／不在籍日数計算方式のいずれかを選択
> - **利用可能な値**：所定出勤日数（暦日数／平日）、不在籍日数（暦日数／平日）
> - **計算の基礎**：各支給項目の詳細設定（3-5節）で「日割り計算基礎」にチェックした項目の合計額が使われる
>
> なお、所定出勤日数・不在籍日数は[[15_基本設定_年度_指示書]]の「休日設定」「独自休日設定」をもとに自動計算される旨が明記されており、支給項目・年度設定・従業員の入退社日の3情報が連動する機能であることが判明した。

## 5. デザインルール

- 基本設定配下の共通タブ（全般〜システム）は[[04_給与計算_設計書]]・[[05_従業員情報_指示書]]と同じ下線＋青字のタブスタイルを踏襲
- 「保存する」金色ボタンは画面最下部固定で、[[05_従業員情報_指示書]]のカード編集時「更新する」ボタンと同系色（マネーフォワード共通のプライマリアクション色）
- テーブルは項目数が多いため横長・高密度なレイアウトで、[[04_給与計算_設計書]]の「項目名（左）／数値（右揃え）」パターンとは異なる「多列の設定フォームをテーブル化する」新パターン。自社実装でも設定系マスタ画面はこのような高密度テーブル＋行内ドロップダウン群の構成を踏襲することを推奨
- 詳細設定はモーダル（ポップオーバー）による段階的開示（プログレッシブディスクロージャー）を採用。標準的な数式パラメータは行内、税・保険計算フラグ等の詳細設定は別モーダルに分離する設計思想

## 6. 拡張・連携ポイント

- **[[04_給与計算_設計書]]との連携が最重要**：本画面でチェックON・計算式設定した支給項目が、給与計算画面の3カラム内訳テーブル「支給」列にそのまま反映される。自社実装では「支給項目マスタ」テーブル（本画面相当）を給与計算ロジックの起点とし、給与計算画面側は本マスタを動的に読み込んでレンダリングする設計が必須
- 給与区分（月給／時給／日給／賞与）ごとに別マスタを持つ構造は、[[05_従業員情報_指示書]]の「業務情報」カードにある「給与区分（月給制／時給制／日給制のラジオ）」と対応関係にあると推測される。従業員の給与区分設定に応じて、給与計算時にどの支給項目マスタ（本画面のどのサブタブ）を参照するかが決まる設計と考えられる（要実機確認）
- 詳細設定の「社会保険の計算対象」「所得税の計算対象」「労働保険の計算対象」フラグは、基本設定配下の「社会保険」「住民税」タブ（本キャプチャ範囲外）の保険料・税額計算式に、どの支給項目を合算基礎に含めるかを制御していると推測される。自社実装でも支給項目マスタに同様の真偽値フラグを持たせ、税・保険計算ロジックから参照する設計が必要
- 固定残業手当系項目は[[11_基本設定_勤怠項目_指示書]]の「法定外時間」「深夜法定外時間」等の勤怠項目と数式内で直接連動している（例：固定残業超過分手当＝法定外時間(平日)－固定残業時間（みなし））。支給項目マスタと勤怠項目マスタは相互参照する設計であることに留意

## 7. 個人情報保護に関する対応メモ

- 画像ヘッダーに映り込んでいた実在の会社名・ログインユーザー名は、本書はもちろん今後作成するどの資料にも転記していません
- 本画面はマスタ設定画面のため、数値欄はいずれも「0」や「1.0」等の初期値プレースホルダーであり、実在の給与額・個人に紐づくデータは表示されていません
- 別AIへの実装指示時も、本書の項目ラベル・レイアウト構造のみを渡し、元画像自体は渡さないことを推奨します
- 元画像ファイル自体（`基本設定/支給項目/`フォルダ内）にはヘッダー部分に会社名・ユーザー名が残存しているため、他者と共有する際はご注意ください
