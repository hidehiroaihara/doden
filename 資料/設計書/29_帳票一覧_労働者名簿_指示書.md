# 労働者名簿（帳票一覧）指示書

参照元：マネーフォワード クラウド給与「帳票一覧＞労働者名簿」画面
取得資料：画像1枚（一覧画面）＋PDF1枚（個別従業員の労働者名簿帳票フォーマット）

> 🔒 **個人情報の取扱いについて**：参照元の画像・PDFには実在の会社名・従業員氏名・従業員番号・住所・生年月日等が含まれていましたが（PDFのファイル名にも実在氏名が含まれます）、本書には一切転記していません。以下は画面構造・帳票レイアウト・項目ラベルのみを抽出したものです。

## 1. 画面概要

| 項目 | 内容 |
|---|---|
| 画面名 | 労働者名簿（帳票一覧配下） |
| 目的 | 労働基準法第107条・同施行規則で調製・保存が義務付けられている「労働者名簿」を全従業員分一覧表示し、従業員単位で印刷／PDF出力する |
| 主要ユーザー | 人事・労務担当者 |
| 表示トリガー | サイドナビ「帳票一覧」→「労働者名簿」（「帳票一覧へ戻る」リンクで上位の帳票一覧画面に戻れる） |

## 4. データ構造（項目定義）

### 労働者名簿 帳票項目（法定記載事項に対応）

| 区分 | 項目 | 備考 |
|---|---|---|
| 基本情報 | 氏名、生年月日、性別 | |
| 住所 | 郵便番号、都道府県以下住所 | |
| 業務 | 従事する業務の種類 | 空欄になり得る（本キャプチャでは空欄の個体を確認） |
| 雇用 | 雇入年月日 | 西暦・和暦を併記する表示形式 |
| 退職・死亡 | 年月日、区分、事由 | 在籍中の従業員は空欄表示 |
| 履歴 | （自由記述） | 項目名の定義はなく、罫線のみの記入枠 |

→ 労働基準法第107条が定める労働者名簿の必須記載事項（氏名・生年月日・性別・住所・従事する業務の種類・雇入年月日・退職または死亡の年月日及びその事由）を過不足なく満たす構成になっている。自社実装でも、この項目セットを固定フィールドとして持つ「労働者名簿帳票」テンプレートを用意し、[[05_従業員情報_指示書]]の従業員マスタ（基本情報・在籍情報カード等）の値を差し込んで生成する設計が妥当と考えられる。

> 📌 **公式サポートサイトでの補足確認**（[労働者名簿の出力方法](https://biz.moneyforward.com/support/payroll/faq/management/mana02.html)、[帳票一覧の使い方](https://biz.moneyforward.com/support/payroll/guide/management02/mana03.html#roudousyameibo)より）：
> - 出力対象項目は「労働基準法施行規則第53条に準拠した項目」と明記されており、法令準拠であることが公式に確認できた。
> - 出力形式は「用紙サイズ：A4」「対応ブラウザ：Google Chromeなど標準的なブラウザ」「印刷またはダウンロードのいずれかを選択可能」と明記されている。
> - **重要な制限事項として「『履歴』と『従事する業務の種類』は未対応のため、印刷後に手作業での補記が必要」と明記されている**。これにより8章の「『従事する業務の種類』欄の入力元」「『履歴』欄の記入方法」の両方が解決：いずれも従業員マスタと連動する項目ではなく、システムが自動出力しない空欄であり、紙に印刷した後に手書きで補記する運用が前提となっている。
> - mana03.html側では、労働者名簿は「反映時期：常時参照可能（特定の反映時期なし）」「記載内容：氏名、従業員番号、契約種別、給与形態、在籍状況」「出力方法：1名ずつ印刷可能」と説明されている（一覧テーブルの表示列と一致）。

## 5. デザインルール

- 一覧テーブルの列構成・リンク付き氏名・契約種別/給与区分/在籍状況の表記は[[05_従業員情報_指示書]]の従業員一覧テーブルと同一のマスタ・表記ルールを踏襲
- 帳票（2-2）は画面系のUIコンポーネント（ドロップダウン・カード）とは異なり、罫線で囲った「印刷帳票」専用のレイアウトパターン。今回の30番（源泉徴収簿）でも同種の帳票レイアウトが確認されており、帳票一覧配下の各帳票に共通する表現方式と考えられる
- ラベル列に淡いグレー背景を敷き、値列は白背景という配色は、他画面の「ラベル：値」テーブルの配色ルールと同系統

## 6. 拡張・連携ポイント

- 労働者名簿の記載項目（氏名・生年月日・性別・住所・雇入年月日等）はすべて[[05_従業員情報_指示書]]の従業員マスタ（基本情報カード・在籍情報カード）に既存項目として存在する。自社実装でも新規に項目を持たず、従業員マスタから帳票を都度生成する設計が望ましい
- 「退職又は死亡」ブロックは[[05_従業員情報_指示書]]の在籍情報カード（退職年月日／退職区分／退職理由）とほぼ1対1で対応しており、データソースを共通化できる
- 「履歴」欄は現行マスタに対応項目が見当たらないため、部署異動履歴等を別テーブルで保持し帳票側で時系列に描画する仕組みが別途必要になる可能性がある

---

## 7. 個人情報保護に関する対応メモ

- 画像・PDFに含まれていた実在の会社名・従業員氏名・従業員番号・住所・生年月日等は、本書はもちろん今後作成するどの資料にも転記していません
- PDFファイル名自体に実在の氏名が含まれていますが、内容（項目ラベル・レイアウト構造）のみを抽出し、氏名・住所等の実データは転記していません
- 別AIへの実装指示時も、本書の項目ラベル・レイアウト構造のみを渡し、実データは渡さないことを推奨します
- 元画像・PDFファイル自体（`帳簿一覧/労働者名簿/`フォルダ内）には個人情報が残存しているため、他者と共有する際は取り扱いにご注意ください
