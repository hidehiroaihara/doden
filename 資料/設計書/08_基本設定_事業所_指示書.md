# 基本設定／事業所 指示書

参照元：マネーフォワード クラウド給与「基本設定」＞「事業所」タブ
取得資料：画像2枚（事業所一覧／「事業所追加」モーダル）

> 🔒 **個人情報の取扱いについて**：参照元の画像には実在の会社名・拠点名・住所・電話番号等が含まれていましたが、本書には一切転記していません。以下は画面構造・項目ラベル・UIコンポーネントのみを抽出したものです。

---

## 1. 画面概要

| 項目 | 内容 |
|---|---|
| 画面名 | 基本設定／事業所 |
| 目的 | 給与計算の対象となる事業所（本社・支店等）をマスタとして登録・一覧管理し、各事業所の社会保険・労働保険設定への入り口を提供する |
| 主要ユーザー | 給与担当者・システム管理者 |
| 表示トリガー | サイドナビ「基本設定」→タブ「事業所」 |

## 3. コンポーネント仕様

### 3-1. 事業所一覧テーブル

| カラム | 内容 |
|---|---|
| 事業所名 | テキスト（本社および各拠点の名称） |
| 本社かどうか | 「はい」／「いいえ」の文字表示（本社は一覧内で1件のみと推測） |
| 都道府県 | 事業所所在地の都道府県名 |
| 社会保険設定 | リンクテキスト「社会保険設定」。クリックで当該事業所の社会保険設定画面へ遷移すると推測（未取得） |
| 労働保険設定 | リンクテキスト「労働保険設定」。クリックで当該事業所の労働保険設定画面へ遷移すると推測（未取得） |
| 設定 | リンクテキスト「詳細設定」。事業所の詳細情報編集画面への入り口と推測（未取得） |
| 削除 | 赤いゴミ箱アイコン。本社行には表示されず、それ以外の事業所行にのみ表示 |

→ 事業所ごとに「社会保険設定」「労働保険設定」への個別リンクが用意されている点から、[[06_基本設定_全体像_指示書]]の「社会保険」「労働保険」タブは**全社共通設定**と**事業所別の個別設定**の両方を持つ構造である可能性が高い（要実機確認）。

> 📌 **公式サポートサイトでの補足確認**（[事業所の設定方法](https://biz.moneyforward.com/support/payroll/guide/setting/se10.html)より）：事業所の削除は「従業員が所属している場合は削除できない」制約があり、削除するには該当従業員を別の事業所へ移動する必要がある旨が明記されている。また、事業所を削除すると当該事業所の社会保険設定・労働保険設定等のデータも**すべて削除され、復元できない**旨が注意喚起されている。一方、本社指定機能や事業所数の上限についての記載は記事内に見当たらなかった。

### 3-2. 「事業所を追加する」ボタン／事業所追加モーダル

| 項目 | 入力形式 |
|---|---|
| 本社かどうか | ラジオボタン（はい／いいえ） |
| 事業所名／事業所名フリガナ | テキスト入力 |
| 郵便番号 | テキスト入力 |
| 都道府県 | ドロップダウン |
| 住所1／住所1カナ／住所2／住所2カナ | テキスト入力（住所2は建物名等の任意項目と推測） |
| 電話番号／FAX番号 | テキスト入力 |
| URL | テキスト入力 |
| 事業主役職名／事業主名／事業主名フリガナ | テキスト入力 |
| フッターボタン | 「登録する」（金色・主アクション）／「キャンセル」（グレー） |

- モーダルはスクロール不要の単一フォームとして全項目が縦に並ぶ構成
- 入力項目のうち住所・氏名系はいずれも「本体＋フリガナ（カナ）」のペアで構成されており、[[05_従業員情報_指示書]]の「基本情報カード」（氏名・住所・フリガナ入力パターン）と同一の設計思想

## 5. デザインルール

- 一覧テーブル右上の「◯◯を追加する」ボタン（カーキ系）は、[[08_基本設定_事業所_指示書]]で確認したこのボタン単体のみだが、[[04_給与計算_設計書]]・[[05_従業員情報_指示書]]のドロップダウンボタンと近い配色系統。新規追加系ボタンとして統一意匠を採用していると推測
- モーダルのフォームは「ラベル（左・グレー背景）／入力欄（右）」の2列パターンで統一。[[07_基本設定_全般_指示書]]の各編集モーダルと共通のフォームスタイル
- 削除アイコンは赤いゴミ箱で統一（[[07_基本設定_全般_指示書]]の部門・支払口座リストの削除アイコンと共通）

---

## 6. 拡張・連携ポイント

- 事業所マスタは、給与計算・従業員情報双方の「所属事業所」選択肢の一次登録場所であるため、自社実装でも他画面より先にこの事業所マスタ管理機能を実装する必要がある
- 事業所ごとに「社会保険設定」「労働保険設定」への個別導線がある構造から、複数事業所を持つ企業では保険料率・適用事業所番号等を事業所単位で管理する設計になっていると推測される。自社実装でも保険関連マスタは事業所IDに紐づく構造で設計する必要がある
- 本社は削除不可（削除アイコン非表示）という制約がある一方、本社以外は削除可能。自社実装でも「本社は最低1件必須・削除不可」というバリデーションルールを踏襲するのが妥当

---

## 7. 個人情報保護に関する対応メモ

- 画像内の実在の会社名・拠点名・住所・電話番号・FAX番号・事業主氏名等は、本書はもちろん今後作成するどの資料にも転記していません
- 別AIへの実装指示時も、本書の項目ラベル・レイアウト構造のみを渡し、実データは渡さないことを推奨します
- 元画像ファイル自体（`基本設定/事業所/`フォルダ内）には会社名・拠点名・住所・電話番号・事業主氏名等が残存しているため、他者と共有する際は取り扱いにご注意ください
