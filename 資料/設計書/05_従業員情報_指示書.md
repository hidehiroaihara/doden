### 3-5. 従業員詳細パネル／各カード共通仕様

- 通常表示は「ラベル：値」の2列（[[04_給与計算_設計書]]・[[01_ホーム画面_設計書]]と共通のテーブルスタイルを踏襲）
- カード右上に「✏編集」リンク。クリックすると**そのカードのみ**がインライン編集モードに切り替わり、他カードは表示のまま変化しない
- 編集モードでは右上が「✕キャンセル」に変わり、カード末尾に金色の「更新する」ボタンが出現。更新はカード単位で個別に送信される（画面全体を1フォームとして送信する設計ではない）
- 唯一「在籍情報」カードのみ、更新ボタンの文言が「更新する」ではなく「在籍状況を変更する」という専用ラベル（在籍状態の変更を他の項目更新より重い操作として扱っていると推測）

## 4. データ構造（項目定義）

### 従業員マスタ 主要項目（一覧表示分）

| 区分 | 項目 |
|---|---|
| 識別 | 従業員番号、氏名 |
| 組織 | 所属事業所、部門、職種、役職 |
| 雇用条件 | 契約種別、給与区分、締め日グループ、1日の所定労働時間、所定労働日数／時間（月平均） |
| 在籍 | 在籍状況、入社年月日、退職年月日、退職区分、退職理由 |
| 休職 | 休職・休業開始日／終了日、種別、支給項目の計算方法、メモ |
| 税務 | 税額表区分、寡婦／ひとり親／障害者／勤労学生／未成年者／災害者／外国人／居住者の各区分 |
| 住民税 | 給与支払報告書提出先市区町村、納付先市区町村、宛名番号、受給者番号 |
| 扶養 | 配偶者有無、扶養家族（氏名、生年月日、続柄、マイナンバー、同居区分、源泉控除対象区分） |
| 連携 | 勤怠連携状態（一覧の「勤怠」列アイコン） |

→ [[04_給与計算_設計書]]の「1日の所定労働時間」「所定労働日数（月平均）」「所定労働時間（月平均）」は本画面の「業務情報」カードで登録した値が参照される関係。マスタの一次登録場所は本画面（従業員情報）であると特定できた。

## 5. デザインルール

- **セクション単位インライン編集**（カードごとに独立した編集／キャンセル／更新）は、[[04_給与計算_設計書]]で確認したヘッダー一括ドロップダウン型のUIとは異なる新しいパターン。自社実装でも「情報カテゴリ（基本情報・在籍情報・業務情報…）ごとに独立したフォーム状態を持たせる」設計が必要
- スライドオーバーパネルは一覧のコンテキスト（絞り込み条件・スクロール位置）を保持したまま詳細を確認させる設計。フルページ遷移にすると一覧状態が失われるため、自社実装でも部分遷移（モーダル／サイドパネル）を推奨
- 「従業員の追加/更新」ドロップダウンボタンは[[04_給与計算_設計書]]のメモ／振込業務／メニューボタンと共通コンポーネントを再利用
- 表示専用テーブルは「ラベル（左）／値（右）」の2列パターンで統一し、[[01_ホーム画面_設計書]]〜[[04_給与計算_設計書]]まで一貫したテーブルスタイルを踏襲

## 6. 拡張・連携ポイント

- 勤怠クラウドとの自動連携（バナー通知＋「クラウド勤怠の従業員と紐づける」メニュー）、eLTAX連携、弥生給与データ移行など、外部システム連携・移行の起点がすべて本画面の「従業員の追加/更新」メニューに集約されている。自社実装でも従業員マスタのインポート／外部連携機能はこの画面に相当する場所へ集約する設計を推奨
- 休職・休業情報の「支給項目の計算方法（例：すべての支給項目を0円にする）」は[[04_給与計算_設計書]]の支給項目マスタと連動する想定。休職中は特定の支給項目を自動的に0円扱いにする、といったロジックの実装が必要
- 「勤怠」列のチェックアイコンは、本画面の従業員が[[04_給与計算_設計書]]の給与計算対象者リストにどう反映されるかの前提データになっていると推測される（要実機確認）

> 📌 **公式サポートサイトでの補足確認**：
> - 契約変更（[従業員の契約変更時に行うこと(昇給・住所変更・結婚・休職・再雇用など)](https://biz.moneyforward.com/support/payroll/guide/howto-employee/hel02.html)）：再雇用時は既存レコードを在籍状態に戻すのではなく、新規に従業員情報を追加する運用が想定されており、同一の従業員番号を使い回す場合は退職前の番号に「old_」を付与するといった運用上の工夫が案内されている。結婚等による扶養情報変更は「一般情報」タブの「扶養情報」で配偶者チェックボックスON、出生時は「扶養追加」から入力欄を表示させる操作
> - eLTAX連携（[eLTAXから住民税特別徴収税額通知CSVをインポートする方法](https://biz.moneyforward.com/support/payroll/guide/howto-employee/hel04.html)）：インポートの前提として「住民税」カードの「受給者番号」（20桁以内）の事前入力が必須。横浜市・名古屋市を納付先とする従業員は自動取込の対象外で、直接入力または従業員情報CSVでの設定が必要。新年度分は「5月支給分の給与計算確定処理後」に取り込むことが推奨されている
> - 入社時フロー（[従業員が入社した時に行う操作について](https://biz.moneyforward.com/support/payroll/guide/howto-employee/hel01.html)）：本画面での従業員情報登録は「①従業員情報の登録 → ②メールアドレスによる従業員の招待 → ③招待メールからの初回ログイン」という3段階フローの最初のステップと位置づけられている

## 7. 個人情報保護に関する対応メモ

- 画像・画面収録動画に映り込んでいた実在の会社名・従業員氏名・住所・生年月日・従業員番号・ログインユーザー名等は、本書はもちろん今後作成するどの資料にも転記していません
- 別AIへの実装指示時も、本書の項目ラベル・レイアウト構造のみを渡し、実データは渡さないことを推奨します
- 元画像・動画ファイル自体（`従業員情報/`フォルダ内）には個人情報が残存しています。特に画面収録動画は基本情報カードの住所・生年月日欄が実データのまま映っているため、他者と共有する際は取り扱いにご注意ください（マイナンバー欄は本キャプチャでは空欄のケースが大半でした）
