## 3. コンポーネント仕様

### 3-1. ヘッダーコントロール群

| 要素 | 内容 |
|---|---|
| 帳票一覧へ戻るリンク | 左上に常設。帳票一覧トップへ戻る |
| PDFの一括作成 | 画面右上のボタン。対象年度の全退職者分をまとめてPDF化する機能と推測（詳細未取得） |
| 手入力 | 選択中の退職者の帳票内容を手動で修正するボタンと推測（編集フォーム未取得） |
| 印刷 | クリックするとブラウザの印刷プレビューが開き、画面のUIクローム（サイドナビ・ヘッダー等）を含まない帳票単体の印刷用PDFが表示される（後述3-4） |
| PDF | 選択中の退職者1名分の源泉徴収票PDFをダウンロードするボタンと推測 |

### 3-2. 絞り込みフィルタ

| フィルタ | 種別 | 備考 |

### 3-3. 退職者リスト

| 要素 | 内容 |

### 3-4. 帳票アクションと印刷プレビュー

- 「印刷」ボタン押下時の挙動を別途スクリーンショットで確認：ブラウザ標準の印刷プレビュー画面が開き、そこに表示されるのは源泉徴収票の帳票部分のみ（サイドナビ・ヘッダー・フィルタ等の画面UIは含まれない）
- 印刷プレビューの元データはPDF形式で保持されている（プレビュー上部に印刷／ダウンロード等の標準ブラウザPDFビューワー操作が表示される）

### 3-5. 源泉徴収票フォーム本体（法定様式）

| ブロック | 主な項目 |
|---|---|
| ヘッダー | 「令和◯◯年分　給与所得の源泉徴収票」／受給者番号／役職名 |
| 支払を受ける者 | 住所又は居所／氏名（フリガナ） |
| 支払金額区分 | 種別（例：給与・賞与）／支払金額／給与所得控除後の金額（調整控除後）／所得控除の額の合計額／源泉徴収税額 |
| 控除対象配偶者等 | （源泉）控除対象配偶者の有無等／配偶者（特別）控除の額 |
| 扶養親族区分 | 控除対象扶養親族等の数（特定／老人／その他）／16歳未満扶養親族の数／障害者の数（特別／その他）／非居住者である親族の数 |
| 保険料等控除 | 特定親族特別控除の額／社会保険料等の金額／生命保険料の控除額／地震保険料の控除額／住宅借入金等特別控除の額 |
| 摘要 | フリーテキスト欄（年末調整未済等のステータス文言が入る想定） |
| 保険料内訳 | 生命保険料の金額の内訳（新生命保険料／旧生命保険料／介護医療保険料／新個人年金保険料／旧個人年金保険料） |
| 住宅借入金等特別控除内訳 | 住宅借入金等特別控除適用数／居住開始年月日（1回目・2回目）／控除区分／年末残高 等 |
| 控除対象配偶者・扶養親族の明細 | （源泉・特別）控除対象配偶者、控除対象扶養親族等1〜4、16歳未満の扶養親族1〜4（各：フリガナ／氏名／区分） |
| チェック区分 | 未成年者／外国人／死亡退職／災害者／乙欄／本人が障害者（特別・その他）／寡婦／ひとり親／勤労学生 |
| 中途就・退職 | 就職・退職の年月日 |
| 受給者生年月日 | 元号／年／月／日 |
| 支払者 | 住所（居所）又は所在地／氏名又は名称／電話番号 |

- 本フォームは国税庁が定める法定調書「給与所得の源泉徴収票」の様式にそのまま準拠した固定レイアウトであり、自社の一般的なテーブルUI（[[04_給与計算_設計書]]等）とは別建てで「法定様式ネイティブレイアウト」として実装する必要がある

## 4. データ構造（項目定義）

### 退職者源泉徴収票 主要項目カテゴリ

| 区分 | 項目 |
|---|---|
| 対象者情報 | 受給者番号、氏名、住所、生年月日 |
| 支払金額 | 種別、支払金額、給与所得控除後の金額、所得控除の額の合計額、源泉徴収税額 |
| 配偶者・扶養 | 控除対象配偶者の有無・控除額、控除対象扶養親族数（区分別）、16歳未満扶養親族数、障害者数 |
| 保険料控除 | 社会保険料等の金額、生命保険料の控除額、地震保険料の控除額、住宅借入金等特別控除の額 |
| 退職情報 | 就職年月日、退職年月日、中途就・退職の別 |
| 支払者情報 | 住所又は所在地、氏名又は名称、電話番号 |
| ステータス | 摘要欄の文言（例：年調未済／年調済 等、年末調整の実施状況を示すと推測） |

→ 本帳票の生成には、[[05_従業員情報_指示書]]の「在籍情報」カード（退職年月日・退職区分）および「税務」「扶養情報」カードの登録値、[[04_給与計算_設計書]]で確定した給与・賞与の支払金額・控除額の累計が参照されていると推測される。自社実装でも、退職者の源泉徴収票は「従業員マスタ＋給与計算確定データ」から自動集計・自動生成する設計が必要。

## 5. デザインルール

- 左側の絞り込み＋対象者リストの構成・検索ボックスの意匠は[[04_給与計算_設計書]]・[[05_従業員情報_指示書]]と共通のマスタ・ディテールパターンを踏襲
- 帳票本体（3-5）のみ、社内共通のテーブルスタイル（グレー罫線・2列パターン等）を使わず、国税庁様式のマス目レイアウトを忠実に再現する必要がある特殊画面。自社実装でも「法定様式帳票」カテゴリとして専用コンポーネント群を用意することを推奨
- 「印刷」ボタンでUIクロームを除いた帳票のみを別プレビューに切り出す設計は、他の帳票（[[26_帳票一覧_賃金台帳_指示書]]の「印刷」ボタン等）でも共通と推測される

## 6. 拡張・連携ポイント

- 公式サポートページ（下記参考リンク）によれば、退職者の源泉徴収票は「退職者の給与または賞与計算の確定処理を最後に行った年度の帳票が作成される」仕組みであり、**従業員に退職日を登録すると自動作成される**（手動作成は不要）。帳票には「退職時までの給与支払金額や、徴収した社会保険料の金額など」が記録される

> 📌 **公式サポートサイトでの補足確認**（[従業員が退職した](https://biz.moneyforward.com/support/payroll/guide/howto-employee/hel03.html)より）：退職時の一連の操作手順が確認できた。①従業員情報の「一般情報」＞「在籍情報」の「編集」から退職年月日・退職区分・退職理由を設定（退職日を設定すると社会保険・雇用保険の資格喪失日が自動的に設定されるが、退職年月日を後から変更・削除しても資格喪失日には自動反映されないため手動修正が必要、との注意あり）→②「帳票一覧」＞「退職者の源泉徴収票」から出力（この際「**最後に支払う給与計算の確定後に出力を行ってください**」という運用上の注記が明記されている）→③退職者のログイン権限を削除（メンバー管理から削除、または「ログイン権限失効日」を設定。削除してもデータ自体は消えない）。また、「退職者の給与支払報告書」（[[18_帳票一覧_全体像_指示書]]で確認した2020年分までの旧帳票群の1つ）は「年末調整機能で作成済みの場合のみ2020年度まで対応」との条件付き記載があり、本画面（退職者の源泉徴収票）とは別の帳票として案内されている。
- 自社実装でも、退職日の登録（[[05_従業員情報_指示書]]の「在籍情報」カード）をトリガーに、退職時点までの給与計算確定データを自動集計して源泉徴収票を生成するバッチ／イベント駆動処理を設計する必要がある
- 「手入力」ボタンは、外部データ連携等で自動反映されない項目（住宅借入金等特別控除など）を手動補正するための機能と推測される（要実機確認）
- 「PDFの一括作成」は対象年度の退職者全員分をまとめて出力する機能と推測（要実機確認）
- 所得税法上、退職者への源泉徴収票交付には法定の期限があるとされているが、本ページからは期限の明記は確認できなかったため、実装時は別途税務要件を確認すること

## 7. 個人情報保護に関する対応メモ

- 画像・PDFに含まれていた実在の従業員氏名・住所（都道府県）・支払金額・源泉徴収税額・事業所名・電話番号・受給者生年月日等は、この設計書には一切転記していません
- 対象PDFファイルのファイル名自体に退職者の実在氏名が含まれています。他者と共有する際は、ファイル名も含めて取り扱いに細心の注意を払ってください
- 一覧画面（FireShot Capture 101）には他の退職者複数名の氏名がリスト表示された状態が写り込んでいますが、これも本書には転記していません
- 別AIへの実装指示時も、本書の帳票様式・項目ラベル・レイアウト構造のみを渡し、実データ・実ファイルは渡さないことを推奨します
- 元画像・PDFファイル自体（`退職者の源泉徴収票/`フォルダ内）には個人情報が残存しているため、他者と共有する際は取り扱いにご注意ください
