# 帳票一覧／給与明細 指示書

参照元：マネーフォワード クラウド給与「帳票一覧＞給与明細」画面
取得資料：画像2枚（一覧画面／従業員別の明細プレビューパネル）＋PDF1枚（明細書の印刷レイアウト）＋ユーザー本人による機能要望メモ1件

> 🔒 **個人情報の取扱いについて**：参照元の画像・PDFには実在の会社名・従業員氏名・従業員番号・所属・勤怠実績・給与金額等が含まれていましたが、本書には一切転記していません。以下は画面構造・項目ラベル・UIコンポーネントのみを抽出したものです。

## 0. ユーザー要望（実装必須要件）

本画面に関して、キャプチャ画像とは別に、ユーザー本人（発注者）から以下の機能要望が明確に伝えられている。これは他章の「画面構造の言語化」とは性質が異なり、**自社実装における優先実装要件**として扱う。

> 給与明細を吐き出す際に、1従業員単位で期間を指定して、月ごとの給与明細をまとめて書き出せるようにしたい。期（半期・四半期・年度等）ごとの提出書類として使うため、そのような機能が必要。
>
> 期間を指定した後、対象の従業員にチェックを入れてZIPダウンロードすると、ZIPファイルの中が「従業員ごとのフォルダ」に分かれており、その従業員フォルダの中にさらに「月ごとのフォルダ」が分かれ、各月のフォルダの中に給与明細PDFが1枚入っている、という階層構造でダウンロードできるようにしたい。

要件を構造化すると以下の3点に整理できる。

| # | 要件 | 補足 |
|---|---|---|
| 1 | 期間指定 | 単月だけでなく「開始月〜終了月」の範囲（期）を1回の操作で指定できること |
| 2 | 従業員の複数選択 | 期間指定後、対象従業員を一覧からチェックボックスで複数選択できること（本画面3-3節の一覧チェックボックスの拡張として実現可能） |
| 3 | ZIP階層ダウンロード | 出力形式は ZIP。ZIP直下＝従業員ごとのフォルダ、その配下＝月ごとのフォルダ、その配下＝当該月の給与明細PDF、という3階層構造 |

ZIPの想定ディレクトリ構造イメージ：

```
給与明細_20XX年X月〜20XX年Y月.zip
├─ 従業員001_氏名/
│   ├─ 2026年04月/
│   │   └─ 給与明細_2026年04月分.pdf
│   ├─ 2026年05月/
│   │   └─ 給与明細_2026年05月分.pdf
│   └─ 2026年06月/
│       └─ 給与明細_2026年06月分.pdf
├─ 従業員003_氏名/
│   ├─ 2026年04月/
│   │   └─ 給与明細_2026年04月分.pdf
│   └─ ...
└─ ...
```

この要望への実装アプローチは「6. 拡張・連携ポイント」で詳述する。

## 3. コンポーネント仕様

> 📌 **公式サポートサイトでの補足確認**（[帳票一覧の使い方](https://biz.moneyforward.com/support/payroll/guide/management02/mana03.html#kyuyomeisai)、[給与・賞与計算の確定処理から明細の印刷までの流れ](https://biz.moneyforward.com/support/payroll/guide/howto-payroll/hpr03.html)より）：
> - 給与明細は「給与計算の確定時に自動作成」される帳票であり、表示項目は別途「明細設定」という設定画面で設定可能との記載がある（本プロジェクトでは「明細設定」画面自体は未取得）。
> - 帳票一覧の給与明細画面には「PDFの一括作成」（複数明細をまとめてPDF化）「印刷」（直接印刷）「PDF」（個別PDF出力）の3つの出力方法があると明記されている。これは3-4節・3-5節で確認したボタン構成と一致する。
> - 従業員をメンバーとして追加すると、従業員自身が「給与明細」画面にログインし「印刷」「PDF」のいずれかで自分の明細を出力できる。明細公開時にメールで従業員へ通知することも可能、との記載がある。
> - 重要な注意事項として「スマートフォンでは出力不可（PCモード切り替えまたはPC操作が必要）」「用紙サイズはA4縦向きで固定」「備考欄は最大50行まで表示可能」の3点が明記されている。

## 6. 拡張・連携ポイント

### 6-1. 既存の連携ポイント

- 明細プレビューの4カラムは[[04_給与計算_設計書]]の給与計算データをそのまま参照する形になっており、自社実装でも「給与計算結果テーブル」を単一のソースとして、給与計算画面・本画面（帳票出力）の両方から参照する設計を推奨
- PDF一括作成は非同期ジョブ＋通知バナーという構成。自社実装でも大量PDF生成はキュー処理（バックグラウンドジョブ）とし、画面をブロックしない設計にする

### 6-2. 0章の要望に対する実装アプローチ（優先実装要件）

0章に記載した「1従業員単位・期間指定でのZIP一括ダウンロード」を実現するため、以下の実装を推奨する。

1. **期間選択UI（レンジピッカー）の追加**
   現行の支給期間セレクタ（単月選択）とは別に、「開始月」「終了月」を選べるレンジ選択コンポーネントを一覧画面に追加する。既存の支給期間ドロップダウン（年単位ページング＋期間リスト）のUIパターンを流用し、開始月用・終了月用の2つのセレクタとして拡張するのが実装コストを抑えやすい。

2. **対象従業員の複数選択**
   3-4節で確認した一覧テーブルのチェックボックス（「すべて選択」含む）をそのまま流用する。現行は「同一支給期間内の複数従業員」を選ぶUIだが、期間レンジが指定された状態でも同じチェックボックスUIで従業員を複数選択できるようにする。

3. **ZIP生成バッチ処理（非同期ジョブ）**
   - 選択された「従業員×期間内の各月」の組み合わせごとに、既存の給与明細PDF生成ロジック（3-5節のプレビュー／PDFレイアウトを流用）を呼び出してPDFを生成する
   - 生成したPDFを `従業員フォルダ／月フォルダ／PDFファイル` の階層でZIPにまとめる（0章のディレクトリ構造イメージを参照）
   - 処理は同期実行せず、3-1節で確認した「PDF一括作成完了バナー」と同じ非同期ジョブ＋完了通知バナーのUXパターンを踏襲する（ZIPが大きくなる可能性があるため、特に非同期化が重要）
   - フォルダ名・ファイル名の命名規則（従業員番号／氏名の併記、月表記の形式など）は要件定義時に別途詰める必要がある

4. **画面上の導線**
   一覧画面のツールバー（「すべて選択」「PDFの一括作成」ボタン周辺）に、「期間を指定してZIPダウンロード」のような新規ボタン／モーダルを追加し、（期間レンジ選択）→（対象従業員チェック）→（ZIP生成実行）→（完了バナーからダウンロード）という導線でつなぐのが、既存UIとの一貫性の観点から自然な設計となる。

## 7. 個人情報保護に関する対応メモ

- 画像・PDFに映り込んでいた実在の会社名・従業員氏名・従業員番号・所属・勤怠実績・給与金額（基本給・手当・控除・差引支給額等）は、本書はもちろん今後作成するどの資料にも転記していません
- 別AIへの実装指示時も、本書の項目ラベル・レイアウト構造・0章の要望内容のみを渡し、実データは渡さないことを推奨します（0章の要望内容自体はユーザー本人の業務要望であり個人情報を含まないため、そのまま実装指示に利用して問題ありません）
- 元画像・PDFファイル自体（`帳簿一覧/給与明細/`フォルダ内）には個人情報が残存しています。特にPDFファイルは氏名・所属・従業員番号・勤怠実績・給与金額が実データのまま記載されているため、他者と共有する際は取り扱いにご注意ください
